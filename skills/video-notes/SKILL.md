# Video Notes

Input: a local video, matching SRT or timestamped JSON, output directory, and optional source URL/title. Obtain missing media or transcription through the caller's existing tools. Keep the source's part number and original timeline. This skill produces notes directly, without a learning catalog or knowledge-management workflow.

Default to a cleaned, faithful lecture script: retain the speaker's voice, substantive content and original sequence. Readability comes from punctuation, paragraphing, clear recognition corrections and well-placed screenshots. Use summary mode only when the user explicitly requests condensation; a request for notes, attractive formatting or readable prose does not imply summarization.

Use `scripts/video-notes` relative to this skill. Requires uv and FFprobe. Locate the available `video-frames` skill through the host or an explicit caller-supplied path; read its CLI contract for image operations. Core instructions are model-independent; use the host's file, image and command tools.

1. **Prepare.** Read [the output contract](references/output-contract.md). Verify media/transcript identity using metadata and matching content at the beginning, middle and end; record the evidence. Run `prepare --mode faithful` by default; `--mode summary` requires an explicit user request. Reopen only a job with matching mode and inputs. Use `--start/--end` for a sample. Existing inputs with different fingerprints need a new work directory, preserving old drafts.
2. **Write.** Read [the note style](references/note-style.md). For each pending window, read all its owned transcript segments and view contact sheets from that same range. Keep a little prior context for continuity. Write its Markdown chunk; record proposed figure IDs, times, source IDs and captions in `note-plan.json`. The model performs this work itself; tools never call another LLM.
3. **Review the window.** Compare every source segment with its draft in order, covering reasons, examples, qualifications, meaningful restatements and small operational details. Check the reverse direction for unsupported additions and changed speaker voice. Resolve omissions before using `review` to save explicit text/visual evidence and a useful note. A large character reduction triggers another full comparison, not padding. Save after each window. Review attestations and length metrics are not automatic semantic guarantees.
4. **Merge and capture.** Read every chunk in order, concatenate into `draft.md`, remove only mechanical overlap and repair sentence joins. Preserve the reviewed wording; do not summarize again during merging. Preserve `<!-- figure:ID -->` at each intended location. Capture planned single frames with `video-frames`; open every final image. Adjust times when pictures are transitional, unclear or unrelated. Record each accepted capture's SHA-256 as `reviewed_sha256` in the figure plan.
5. **Deliver.** Run `assemble`, `render`, then `validate`. Inspect the full note against the transcript. Read and execute the [structure and HTML review checklist](references/presentation-review.md), including topic subheadings, complete Markdown/HTML correspondence and actual desktop/narrow page inspection; record observations and untested checks separately. Correct affected drafts/figures and repeat the downstream steps. Return Markdown/HTML paths, source scope, checks and unresolved limitations.

Completion requires every scoped window reviewed, captions grounded in viewed images, actual captures matching the plan, resolved markers and portable local assets. Structural validation complements the caller's content and visual review. With no image-viewing capability, report the missing capability rather than calling an unviewed illustrated result complete.
