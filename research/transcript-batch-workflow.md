# 批量整理转录稿的工作流建议

调研日期：2026-09-28

## 结论

目录可以作为用户的一次性入口，但应先盘点目录，再按课时拆成独立、边界清楚的工作项。每项只处理一节课及其对应的完整转录来源，生成一个单独的 Markdown 文件；完成后，再逐文件对照对应来源做遗漏审查。最多同时运行三个子 Agent；一个独立审稿上下文可复用最多三个小批次，逐篇核查所有稿件。批次大小必须允许完整读取所有来源和成稿并留出报告问题的空间。视频是唯一来源、尚无可读转录时，先本地 ASR 生成转录，再进入讲稿整理流程。

## 官方资料支持的判断

- OpenAI 的多 Agent 指南建议把相互独立、边界明确的任务交给子 Agent，例如分别处理不同文档；每个子 Agent 有自己的上下文，可并行工作，由主 Agent 汇总。短小或依赖前一步结果的任务应留在主 Agent 中。子 Agent 若编辑相同文件，需要协调；使用文件和命令时，子 Agent 与主 Agent 共享文件系统，创建子 Agent 不会创建另一套环境。[Agents API：Multi-agent](https://developers.openai.com/api/docs/guides/agents-api/multi-agent)
- Responses API 的指南指出，独立上下文可以减少无关工作流之间的干扰；但多 Agent 会增加 token 用量，对依赖顺序的任务、共享可变资源或本身很小的任务可能不划算。上下文隔离只能减少跨文档干扰，不能保证没有幻觉或遗漏。[Responses API：Multi-agent](https://developers.openai.com/api/docs/guides/responses-multi-agent)
- OpenAI 将 Skills 描述为可复用的指令和支持文件，可用于编码工作流步骤、决策点和输出要求；Skill 规定怎么做，但不等于质量保证机制。[Skills（OpenAI API）](https://developers.openai.com/api/docs/guides/tools-skills)；[Skills（Plugins）](https://developers.openai.com/plugins/concepts/skills)

我没有找到 OpenAI 针对 Codex 桌面版“批量整理课程转录稿”或“必须启用子 Agent”的专门规定。因此，上述 Agents API 文档支持这种拆分思路，但不能保证当前桌面应用在每次任务中都会自动采用相同的多 Agent 行为。实际使用时，应在请求中明确要求先盘点、按课时处理并逐份审查。

## 推荐操作

1. 用户给出整个目录作为入口，并说明目标输出规范。
2. 先盘点文件，为每一课建立“原始转录 → 讲稿输出”的对应关系；区分转录文本、字幕、元数据、旧稿和排除项。用户确认拒绝的旧稿不进入写作或审查任务。
3. 将每个完整课时及其对应来源作为一个有界工作项。最多同时运行三个子 Agent，每个写作者负责一整课和一个不同输出文件；不要把一节课切给多个写作者。
4. 每批新稿由同一个独立审稿上下文逐篇对照对应的完整转录；该上下文最多复用三批，遇到上下文不足或课时间开始互相干扰时提前重置。中短篇先以每批三篇为起点，长篇减少数量，确保完整来源和成稿都能读完并留有报告空间。审稿仍须覆盖每篇，只合并 Agent 批次，不合并质量判定。
5. 只把未通过项交回修改，并对受影响段落做针对性复查；已通过稿件不重复审查。汇总输入、输出、排除项和未处理项；未完成逐篇核对的课时不要报告为已完成。

若只有视频文件，先用本地 ASR 得到带完整内容的转录，再按上述流程整理。这个步骤是针对本工作流的实用建议，不是 OpenAI 多 Agent 文档规定的专属视频流程。

## 可直接使用的目录请求

> 使用 $learning-transcript 处理这个目录。先列出每一课对应的完整转录来源和输出路径，再逐课时处理。每个工作项只包含一节课及其转录材料；有可读的 TXT/SRT/VTT 时直接使用，不要重新转录。保留讲者所有有信息量的内容及原顺序，只清理停顿、口误、无意义重复和能明确判定的 ASR 错字，不要总结或压缩。每篇写完后，对照该课完整原文检查遗漏与无来源内容，通过后再标记完成。若使用多个 Agent，请分配互不重叠的课时和输出文件，并限制并行数量；最后列出完成、未处理和需人工确认的项目。
