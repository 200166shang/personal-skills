# yt-dlp-download：目录与批量下载扩展方案

状态：历史初稿（2026-10-16），不作为当前执行规则。原文中的输出 schema、批量笔记目录职责及独立仓库位置已有调整；以[当前下载器设计](../design.md)和 Skill 契约为准。

## 1. 目标与边界

扩展已有 `yt-dlp-download` Skill，使外部能够读取课程／列表目录、下载完整列表或指定列表项。复用 yt-dlp 已有能力，不新增目录 Skill、不在笔记批量工具里实现第二份目录抓取或下载逻辑。

保持原有无额外参数的单视频行为、最低画质默认、语言选择、媒体保存根目录及权限边界。批量笔记只消费结构化目录和逐视频下载结果，另行负责模型上下文隔离、写稿、审校与恢复。

## 2. 当前限制与维护位置

已检查的封装中，`_base_options()` 固定 `noplaylist=True`，`_extract()` 主动拒绝 playlist；`_download()` 假设只有一个媒体 ID 和输出目录，`_parser()` 只暴露 inspect/download。因此需要改参数入口与 Python 处理逻辑，不能只删掉 `noplaylist` 就视为完成。

实际安装位置是本机 `~/.codex/skills/yt-dlp-download/`，目前不属于 personal-skills 的已跟踪源码。实施前先确定权威维护位置：已有源码仓库则在该仓库建工作树、新分支和 PR；若确无独立维护仓库，则先将完整的纯 Skill 源文件纳入 personal-skills 的 `skills/yt-dlp-download/`，再修改。虚拟环境、缓存、Cookie、登录状态等不入库。不能只改全局安装副本而没有可审查源码。

## 3. 拟新增入口

```text
yt-dlp-download catalog URL [--cookies-from-browser BROWSER]
yt-dlp-download download URL --media video --playlist
yt-dlp-download download URL --media video --playlist-items 5:9
```

全局 `--data-dir` 仍放子命令之前，例如：

```text
yt-dlp-download --data-dir PATH download URL --media video --playlist-items 5:9
```

- `catalog`：只读取元信息，不下载媒体；返回原顺序条目及准确链接。对于可识别的分 P 容器，即使入口含 p=2，显式 catalog 请求仍发现所属目录，同时记录原入口定位，不将下载范围自动扩大。
- `--playlist`：显式下载完整列表。
- `--playlist-items`：显式开启列表处理并选择位置；与 `--playlist` 同时出现时，选定范围优先，不下载全部。
- 无上述批量参数：保持现有单视频行为，inspect 不变。
- 初版选择表达式支持正整数、闭区间 `5:9` 和逗号组合。非法或空选择在下载前报错。章节标签 2.1 不等于列表序号，标签匹配由笔记调度层完成。

## 4. 结构化输出

### 目录

顶层包含 `ok`、`status`、平台、原入口、容器 ID／标题、目录是否完整及 `entries`。每项包含原始 index、标题、媒体 ID（可确认时）、canonical URL、duration（未知时明确为空）、可用状态及平台元信息。

B 站分 P 保留 BV、cid、page；独立 BV 的合集保留各条目的实际标识。YouTube 保留稳定 video ID。不可用、私有、删除或暂缺元信息的条目不能被静默删除并导致后续序号改变。目录未完整获取时不能声称全集完整。

优先使用 yt-dlp 元信息；某些 flat entry 不包含完整信息时，按需补元信息或明确未知，不用猜测填满字段。各平台具体目录类型必须通过 adapter 验证，而不是假定一个参数能处理所有链接形式。参考：[yt-dlp 官方选项](https://github.com/yt-dlp/yt-dlp#usage-and-options)。

### 下载

原单视频成功返回结构保持兼容。显式批量模式返回：

```json
{
  "ok": false,
  "status": "partial",
  "selected_count": 2,
  "completed_count": 1,
  "failed_count": 1,
  "entries": [
    {"index": 5, "id": "BV11X4y1j7si_p5", "status": "completed", "files": ["<实际文件绝对路径>"]},
    {"index": 6, "id": "BV11X4y1j7si_p6", "status": "failed", "files": [], "error": {"code": "download_failed", "message": "<原因>"}}
  ]
}
```

这是结果结构示意，不是执行结果。每项还应携带准确来源 URL、标题和输出目录。全部完成时退出 0；存在失败时返回非零，但保留结构化逐项结果，不能抛出一个异常就丢失已完成清单。使用 stderr 记录进度；批量部分结果在 stdout 返回，致命目录／参数错误沿用明确的错误契约。

文件必须与本次选定媒体、类型和语言对应，并确认存在；不能把目录里任意旧文件当成新成功。复用已完成文件时明确标记复用，不重新下载。继续使用 `<data-dir>/<platform>/<media-id>/`，不同分 P 独立目录，不把整套媒体平铺到一个课程文件中。

## 5. 内部改动点

| 位置 | 改动 |
| --- | --- |
| `_parser()` | 新增 catalog、playlist 和 playlist-items 参数与验证 |
| 元信息提取 | 区分单视频与目录；只在显式目录／批量模式关闭单视频限制；按平台识别目录和条目 |
| `_download()` | 保留单视频分支；批量分支先固定选项，再逐个处理准确的条目 |
| 单条下载逻辑 | 提取可复用的单媒体函数，语言和文件校验仍逐视频执行 |
| 结果与错误 | 聚合成功／失败／复用项，支持部分成功及重试，不丢状态 |
| `SKILL.md`、CLI 契约 | 更新单视频与列表的选择规则、命令和返回结果 |
| 测试／打包 | 增加目录 fixture、批量行为测试，验证安装后入口和完整文件 |

同一批次请求中文／特定语言字幕时，在每项实际轨道里匹配确切代码；缺失的条目明确失败或返回不可用状态，不能静默替换语言。目录能读取不代表实际媒体可下载，登录／权限／HTTP 412 等按原 Skill 边界处理。

## 6. 与笔记批量功能的连接

1. `yt-dlp-download catalog` 返回目录；批量笔记层精确选择 2.1–2.5，冻结清单。
2. 素材准备可使用批量下载入口预下载选中项，也可按就绪队列逐课调用原单视频入口。调度层不自己下载。
3. 成功项以实际路径交给字幕／ASR及单课笔记执行者；失败项进入对应课时状态，其他已就绪课继续。
4. 小鹅通继续使用原 `xiaoetong-download catalog/download`，不强行通过 yt-dlp；本地输入只盘点文件。批量层仅把这些已返回的数据转换成统一任务模型。

## 7. 开发拆分与测试

- D01：确认源码维护位置、建立新工作树与分支，固定现有单视频契约及测试基线。
- D02：实现 catalog 和目录完整性／条目身份，添加 B 站与 YouTube 结构测试。
- D03：增加显式批量参数、选择解析、逐项下载结果及部分失败处理。
- D04：单视频兼容、语言轨道、复用、安装后入口和批量结果测试；更新 Skill 契约。
- D05：使用本课程 2.1–2.5 验证真实目录和媒体获取，再接入批量笔记整课验收。

必要测试包括：无批量参数仍只处理一个视频；1、3、5:9 等选择准确且不多下载；无效／空范围不产生媒体写入；不可用条目保留位置；一个失败不抹掉其他结果；语言缺失不替换语言；重复执行复用已确认的文件；成功路径确实存在。

本次真实验收为 **P5–P9**：2.1 四种输出模式、2.2 IO 最大输出速度、2.3 LED 闪灯实验、2.4 四种输入模式、2.5 按钮实验。目录已确认，总时长 7322 秒；当前媒体页面检查曾返回 412，实际下载尚未验证。目录事实见[课程核实报告](../../../research/video-notes-batch-course-catalog.md)。
